Prerequisites & Installation

RequirementDetails
Bitbucket Data CenterVersion 8.x or later
TruffleHog binaryv3.x installed on every cluster node
PermissionsSystem Administrator role
NetworkOutbound HTTPS if secret verification or webhooks are used

Install TruffleHog on each node

curl -sSfL https://raw.githubusercontent.com/trufflesecurity/trufflehog/main/scripts/install.sh \
  | sh -s -- -b /usr/local/bin
trufflehog --version

Install the plugin

  1. Log in as System Administrator
  2. Navigate to Administration → Manage apps → Upload app
  3. Upload trufflehog-plugin-<version>.jar
  4. Verify all 15 modules show Enabled and not broken

Email Notifications (v1.1)

Two delivery options
Option A — Bitbucket Mail Server: Leave all SMTP fields blank. Uses the server from Administration → Mail server.

Option B — Direct SMTP: Fill in the SMTP fields to bypass Bitbucket's mail server.
FieldDescription
SMTP hoste.g., smtp.office365.com
SMTP port587 (STARTTLS) or 465 (SSL)
Use TLSEnable STARTTLS
From addressOverride From header, e.g. trufflehog@company.com

Use the Send test button to verify before saving.

Notification mode: Immediate fires after every scan with new findings; Daily digest batches and sends once per day at the configured UTC hour.

Webhook Notifications (v1.1)

  1. Create an Incoming Webhook in Teams or Slack
  2. Paste the URL into the corresponding field in Settings
  3. Click Test to verify

Payload: {"text": "[TruffleHog] N new secret(s) found in PROJECT/repo (V verified)."}

Data Center Per-Node Binary Paths (v1.5)

In clustered deployments, enter one nodeName=path mapping per line:

node1=/usr/local/bin/trufflehog
node2=/opt/trufflehog/bin/trufflehog

Nodes without an entry use the global Executable path.

Per-Secret Allowlist

Permanently suppress a specific finding by adding its SHA-256 fingerprint to the allowlist. Allowlisted findings are invisible in all dashboards and do not trigger notifications.

Config Export / Import (v1.5)

Export settings as JSON (passwords omitted) for backup or environment replication. Import preserves existing passwords if absent in the imported file.

Audit Log (v1.4)

Records all administrative actions including push scans, test notifications, and config imports. Accessible in Settings → Audit log and via:

GET /rest/th-scanner/1.0/audit?limit=100
