About this guide
This guide is for developers who use Bitbucket repositories where the TruffleHog Secret Scanner plugin is installed. It explains push behavior, how to view and respond to findings, and how to request false positive suppression.

What is TruffleHog?

The TruffleHog Secret Scanner plugin automatically detects leaked secrets — API keys, passwords, tokens, certificates, and other credentials — in your Bitbucket repositories. It uses TruffleHog v3, which detects over 700 types of credentials.

Push Behavior

When you push commits, the scanner's response depends on the administrator's configuration:

BLOCK Mode

Your push is rejected if it introduces a verified secret on a protected branch.

remote: [TruffleHog] Push rejected — verified secret detected.
remote: Detector: AWS, File: config/app.properties, Branch: main
remote: Remediate the secret before pushing to protected branches.

What to do:

  1. Rotate the secret immediately
  2. Remove it from your commit history using git filter-repo
  3. Re-push after cleaning the history

WARN Mode

Your push succeeds but a warning is logged and notifications are sent. You may receive an email from the security team.

SILENT Mode

Scans run in the background. You will not be notified, but findings appear in the dashboards.

Finding Statuses

StatusMeaning
OpenNew finding, not yet reviewed
FixedSecret has been rotated and removed from code
False positiveNot actually a secret (e.g., a test value)
Accepted riskKnown, documented risk intentionally tolerated

Viewing Findings

  1. Navigate to your repository in Bitbucket
  2. Click TruffleHog in the left navigation
  3. View open findings, their severity, and remediation status
  4. Click a finding to see the file path, line number, branch, and commit

FAQ

I committed a test API key. What should I do?

Mark the finding as False positive with a note explaining it is a test value. Ask your admin to add it to the allowlist regex if this pattern recurs.

My push was blocked but the secret is in a dependency file.

Ask your admin to add the path prefix (e.g., vendor/, node_modules/) to the excluded directories setting.

I rotated the secret. Now what?

  1. Remove or replace the secret in the codebase
  2. Mark the finding as Fixed with a reason note
  3. If it was in git history, clean with git filter-repo

Why was my push to a feature branch not blocked?

BLOCK mode typically applies only to protected branches (main, master). Feature branches may be in WARN mode.
