Why TruffleHog Secret Scanner?
🔒

Prevent Credential Exposure

Catch secrets the moment they are pushed — before they reach shared or public branches

✅

Verified Detection

TruffleHog checks credentials against live APIs to confirm they are valid, reducing noise

📊

Full Audit Trail

Every finding, status change, and configuration action is logged and searchable

⚖️

Compliance Evidence

Demonstrates active secret-management controls for SOC 2, ISO 27001, and PCI-DSS

🔌

Zero External Deps

Runs entirely within Bitbucket's OSGi container; no external SaaS or cloud service required

🔐

Developer Friendly

Warn on feature branches, block only on protected ones — security without friction

How It Works
Developer push
→
Post-receive hook
→
TruffleHog v3 binary
→
Findings stored (AO)
→
Notifications
Cron scheduler
→
Full repo scan
→
Dashboard & REST API
→
Remediation workflow

Secrets are never stored in plaintext. Only the fingerprint (SHA-256) and redacted value are persisted.

Feature Roadmap & Capabilities
v1.0 — Core

Secret Detection Foundation

Everything needed to start detecting and tracking secrets across all repositories.

  • Post-receive hook scanning
  • Scheduled full-system scans
  • Findings dashboard (system / project / repo)
  • Remediation workflow with notes
  • Per-secret fingerprint allowlist
  • File and directory exclusions
v1.1 — Notifications

Email & Webhook Alerts

Notify the right people the moment secrets are detected.

  • Direct SMTP support (bypass Bitbucket mail server)
  • Microsoft Teams webhook integration
  • Slack webhook integration
  • Immediate vs. daily digest mode
  • Test buttons for all notification channels
  • Separate committer / admin / infosec recipients
v1.2 — Push Enforcement

Block, Warn, or Monitor

Fine-grained control over how the scanner responds to pushes.

  • Block / Warn / Silent push result modes
  • Branch pattern matching (exact + glob)
  • Excluded pusher usernames (CI service accounts)
  • Max file size and total scan size limits
v1.3 — Dashboards

Metrics & Reporting

Visual insights into secret detection trends and remediation health.

  • Scan outcomes donut chart (New / Recurring / Resolved)
  • Top detectors by finding count
  • Top repositories by open finding count
  • Recent events table
  • CSV export for all findings
v1.4 — Custom Detectors

Tuning & Audit

Reduce noise and add custom detectors tailored to your stack.

  • Warn-only detector classification (no blocking)
  • Custom detector config path (TruffleHog YAML)
  • Audit log for all admin actions
  • Audit log REST endpoint
v1.5 — Enterprise / Data Center

Cluster & Proxy Support

Production-ready for multi-node clustered deployments.

  • Per-node TruffleHog binary path configuration
  • HTTP/HTTPS proxy settings with auth
  • Custom SSL certificate for self-signed proxies
  • Configuration export / import (JSON)
  • No-proxy host bypass list

Technical Summary
Component Details
Platform Bitbucket Data Center 8.x, OSGi, Spring (atlassian-spring-scanner 3.0.4)
Persistence Active Objects (cluster-safe JPA), 6 AO tables (AO_501204_*)
Secret engine TruffleHog v3 CLI binary — 700+ detectors, live verification against external APIs
Notifications OSGi-reflected Bitbucket mail server or direct SMTP; Teams/Slack via HttpURLConnection
REST API 14 endpoints under /rest/th-scanner/1.0/, JAX-RS
Build Maven (atlas-mvn package), Atlassian Plugin SDK, WSL build workflow
Plugin key com.acme.bitbucket.trufflehog
